# Миграции: как сверять применённость

## Короткое правило

**Не сравнивай имена файлов со списком `list_migrations`.** Сверяй по объектам в базе.

## Почему

Когда миграцию применяют через Supabase MCP или дашборд, она записывается в
`supabase_migrations.schema_migrations` со СВОИМ номером версии — по времени применения,
а не по имени файла. Одна и та же миграция начинает выглядеть как две разные, а честно
применённая — как пропущенная.

19.08.2026 из-за этого пять файлов числились неприменёнными. Проверка по объектам
показала, что применены **все до единого**. В памяти проекта несколько записей вида
«нужно применить миграцию X» — они порождены этой же иллюзией.

## Как правильно

1. Открой файл миграции и выпиши, что он создаёт: колонку, значение enum, функцию,
   политику, cron-задачу.
2. Проверь наличие этих объектов запросом к `information_schema`, `pg_enum`, `pg_proc`
   или `cron.job`.
3. Объект есть — миграция применена, независимо от того, совпадают ли номера.

Готовый порядок зашит в скилл `/deploy-checklist`.

## Применены, но не записаны в бухгалтерию базы

Эти два файла применены к проду (объекты проверены и на месте), но строки в
`supabase_migrations.schema_migrations` для них нет — их накатывали напрямую через
SQL Editor, минуя механизм версий:

- `20260801125900_appointment_status_enum_values.sql` — значения `pending_payment` и
  `payment_expired` в типе `appointment_status` присутствуют.
- `20260815130000_whatsapp_cloud_api.sql` — присутствуют `salons.wa_provider`,
  `salons.wa_cloud_templates_ready` и все шесть колонок `whatsapp_cloud_*` в
  `salon_secrets`.

Строки бухгалтерии намеренно **не дописаны**: на момент сверки действовала заморозка
прода на время внешнего ревью Meta, а запись в служебную таблицу — всё равно запись в
прод. Дописать можно после разморозки, это метаданные и на поведение приложения они
не влияют:

```sql
insert into supabase_migrations.schema_migrations (version, name)
values ('20260801125900', 'appointment_status_enum_values'),
       ('20260815130000', 'whatsapp_cloud_api')
on conflict (version) do nothing;
```

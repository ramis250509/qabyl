# Локальная база для проверки миграций

Зачем: чтобы менять схему и проверять последствия, не трогая ни боевую базу, ни
Токио. Главное преимущество — `supabase db reset`: пересобирает базу с нуля из
миграций за секунды. На удалённой базе такого нет, там состояние накапливается,
и через десяток итераций уже непонятно, что в ней применено.

Пока проверки редкие, хватает Токио. Ставить Docker имеет смысл перед работами
уровня 2 (единый движок расписания, разделение рабочего дня и перерыва) — там
будут десятки итераций подряд.

---

## Что понадобится

- Windows 10 версии 1903 и новее. У вас 10.0.19045 — подходит.
- Около 10 ГБ на диске и 4 ГБ оперативной памяти, которые Docker займёт под себя.
- Права администратора на компьютере.

---

## Шаг 1. Включить WSL2

Docker на Windows работает поверх подсистемы Linux. Откройте **PowerShell от
имени администратора** (правой кнопкой по «Пуск» → Windows PowerShell (админ)):

```powershell
wsl --install
```

Команда скачает и включит всё нужное. **После неё обязательно перезагрузите
компьютер** — без перезагрузки Docker не запустится.

Если ответит, что WSL уже установлен, — хорошо, идите дальше.

---

## Шаг 2. Поставить Docker Desktop

Скачать с [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/),
выбрать версию для Windows.

При установке оставьте включённой галочку **«Use WSL 2 based engine»** — она
стоит по умолчанию.

После установки запустите Docker Desktop и дождитесь, пока значок кита в трее
перестанет мигать. Первый запуск занимает пару минут.

⚠️ Docker Desktop должен быть **запущен** каждый раз, когда вы работаете с
локальной базой. Если он закрыт, команды ниже будут ругаться, что не видят
Docker.

---

## Шаг 3. Проверить, что всё встало

⚠️ **Сначала закройте и заново откройте приложение, из которого запускаете
команды.** Терминал держит список путей к программам на момент своего запуска, и
про установленный после этого Docker он не знает. Симптом — `docker : The term
'docker' is not recognized`, хотя Docker стоит и работает. Новая вкладка
терминала может не помочь: она наследует окружение от родительского процесса,
нужен именно перезапуск приложения.

На Windows Docker ставится в `%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin`
и прописывается в PATH пользователя автоматически — вручную ничего добавлять не
нужно, достаточно перезапуска.

```bash
docker --version
```

```bash
docker run --rm hello-world
```

Вторая команда скачает крошечный образ и напечатает приветствие. Если напечатала
— Docker рабочий.

---

## Шаг 4. Поднять локальную Qabyl

Из папки проекта:

```bash
npx supabase start
```

Первый запуск скачает образы Postgres, Auth, Storage и прочего — это 2–3 ГБ,
минут пять на нормальном интернете. Дальше запуск будет занимать секунд двадцать.

В конце команда напечатает адреса и ключи локальной копии. Нужная строка —
`DB URL`, она всегда одна и та же:

```
postgresql://postgres:postgres@127.0.0.1:54322/postgres
```

Пароль здесь `postgres` и это нормально: база живёт только на вашем компьютере и
наружу не смотрит.

---

## Шаг 5. Пересобрать базу из миграций

```bash
npx supabase db reset
```

Сносит локальную базу и накатывает все миграции из `supabase/migrations/` по
порядку, с нуля. Это и есть та самая кнопка, ради которой ставится Docker:
сломали схему — нажали, через двадцать секунд чистое состояние.

Заодно это честная проверка, что вся цепочка миграций воспроизводима с нуля —
на Токио мы это проверили один раз вручную и споткнулись о значения
перечислений.

---

## Когда закончили

```bash
npx supabase stop
```

Освободит память. Данные сохранятся до следующего `db reset`.

---

## Что дальше

Прогон поведенческих тестов (`supabase/tests/booking_integrity.sql`) на локальной
базе требует клиента `psql`, которого на Windows по умолчанию нет. Когда возьмёмся
за уровень 2, добавлю в проект одну команду, которая делает всё сама — сейчас
расписывать обходные пути через `docker exec` смысла нет, они хрупкие.

---

## Если что-то пошло не так

| Симптом | Причина |
|---|---|
| `docker : The term 'docker' is not recognized` | терминал открыт до установки — перезапустите приложение целиком (см. шаг 3) |
| `Cannot connect to the Docker daemon` | Docker Desktop закрыт или ещё стартует — дождитесь статуса «Engine running» |
| Внизу окна Docker висит «Engine starting» | первый запуск поднимает виртуальную машину, это пара минут |
| `WSL 2 installation is incomplete` | не перезагрузились после `wsl --install` |
| `supabase start` висит на скачивании | первый запуск, 2–3 ГБ образов, это нормально |
| порт 54322 занят | уже запущен другой проект Supabase — `npx supabase stop --all` |

# До production-ready (срез 12.09.2026)

Цель: довести Qabyl до состояния, когда салон подключается сам, работает и платит, — всё, кроме
автосписания с карты. Автосписание упирается в договор с платёжным шлюзом, остальное — нет.

## Что уже в проде

- **Биллинг.** Тарифы Start / Business / Pro, учёт сообщений, лимиты, пакеты, отсрочка, блокировка
  кабинета и страницы записи. Цены и лимиты — данные в `billing_plans` / `billing_settings`.
  Подробности и юнит-экономика: `docs/PRICING.md`.
- **Оплата переводом.** Реквизиты видит салон в «Тариф и оплата»; владелец платформы отмечает
  оплату кнопкой в `/admin/billing?salon=<id>`.
- **Выключатели биллинга:** общий и по каждому салону (`/admin/billing` у super_admin).
- **Самостоятельное подключение WhatsApp** (Embedded Signup v4), выбор тарифа в мастере,
  поиск личных чатов в «Контактах без Админа».

## Чего нет (в порядке важности)

### 1. Ни один салон не подключён к WhatsApp — сквозного прогона не было

По базе на 12.09: у Lashes Nurzhan, Skin Art и «Эркеайым» нет реквизитов Cloud API,
последнее сообщение у Lashes — 26.08. То есть весь путь «клиент написал → ассистент записал →
ушло подтверждение → посчитался расход» на живом салоне ни разу не проверялся после биллинга.

Прогон (каждый шаг проверяем по базе, не на слово):

1. Подключить Lashes Nurzhan через `/onboarding` → «Подключить WhatsApp».
2. Написать с личного номера на номер салона → ассистент отвечает.
3. Записаться через ассистента → запись появилась в календаре, клиенту ушло подтверждение.
4. Проверить расход: `select * from billing_usage where salon_id = '<id>'`.
5. Записаться через страницу `/book/<slug>` → подтверждение ушло шаблоном (вне 24-часового окна).
6. Напоминание за 2 часа (можно подвинуть `starts_at` у тестовой записи).
7. Снять `billing_exempt`, выставить лимит сообщений в 1 и проверить: ассистент замолкает,
   уведомления идут, в кабинете висит баннер. Вернуть обратно.
8. Поставить `status = 'suspended'` → кабинет закрыт экраном оплаты, страница записи говорит
   «временно недоступна», запись не создаётся. Вернуть обратно.

### 2. Единой кредитной линии нет

Код готов и включается переменными воркера: `YCLOUD_API_KEY`, `WA_ES_SOLUTION_ID`.
Пока их нет, за сообщения Meta платит сам салон картой, привязанной в его WABA, — это
противоречит обещанию «клиент ничего не подключает». Нужно: одобрение YCloud → ключ →
партнёрское решение в Meta (вариант «Only me») → обе переменные в Cloudflare.

### 3. Автосписание с карты

Сейчас деньги приходят переводом вручную. Для автосписания нужно:

- договор с Freedom Pay KG (или Finik — только Кыргызстан; Paddle — без России и Беларуси);
- переменные `FREEDOMPAY_MERCHANT_ID`, `FREEDOMPAY_SECRET_KEY`;
- подтвердить у них имя скрипта повторного списания (`FREEDOMPAY_RECURRING_SCRIPT`,
  по умолчанию `make_recurring_payment.php`) — публично оно не описано;
- тестовый платёж: привязка карты → уведомление на `/api/public/billing/freedompay` →
  продление периода → повторное списание.

Проверка, подключён ли шлюз: `curl -s -o /dev/null -w "%{http_code}" -X POST
https://qabyl.com/api/public/billing/freedompay` — 503 значит «не подключён», 400 значит
«подключён, подпись не сошлась».

### 4. Хвосты

- Текст ошибки лимита писем на `/auth` вводит в заблуждение («подождите минуту» — на самом деле
  это часовой лимит писем Supabase).
- «Эркеайым» и Skin Art без WhatsApp; у «Эркеайым» в базе был личный номер Рамиса (забанен).
- Instagram ни у одного салона не включён.

# Выбор BSP для WhatsApp: оценка 2026-09-02

Контекст: транспорт `src/lib/wa-cloud.server.ts` готов и говорит на формате Meta Cloud API.
Блокирует не код, а **Embedded Signup**: чтобы салон подключался сам, нужно одобренное Meta
приложение + статус Tech Provider. Пока идёт App Review, продажи стоят, а мост через Make —
заплатка, а не решение.

Вопрос эволюции: **чей Meta App использовать, пока свой не одобрен.**

---

## Решение

**360dialog, партнёрский аккаунт, режим Integrated Onboarding, биллинг Partner-Paid.**

Почему именно он — по нашим требованиям:

| Требование | 360dialog | Комментарий |
|---|---|---|
| Онбординг без своего одобренного Meta App | ✅ | Integrated Onboarding идёт на Solution ID 360dialog. Своё приложение нужно только для Partner-Hosted Embedded Signup — это опция, не условие |
| Coexistence (номер остаётся в приложении WhatsApp Business) | ✅ | Поддерживается явно. Ограничения: нет OBA/синей галочки и обычной верификации бизнеса — вместо неё Partner-Led Business Verification (PLBV) или Meta Verified |
| Полный messaging API + вебхуки | ✅ | `https://waba-v2.360dialog.io` + заголовок `D360-API-KEY`; payload и вебхуки в формате Cloud API |
| Отдельная WABA на арендатора | ✅ | Каждый канал — своя WABA и свой `D360-API-KEY` в Partner Hub |
| Салон не вводит карту | ✅ | Модель **Partner-Paid**: все обязательства по WABA несём мы, счёт получаем от 360dialog |
| Без крупного минимума | ⚠️ | Есть месячная платформенная плата за Partner Hub + лицензия за активный канал. Точные цифры — только у сейлза. Порог Premium — от 500 €/$ лицензионных платежей в месяц, до него мы на Growth |
| ≤ $10–12 за WABA | ⚠️ | Подтвердить у сейлза (см. вопросы ниже) |
| Первый клиент за 1–3 дня | ✅ | Партнёрский аккаунт заводится сам, одобрение решения ~24 ч; лимит — 200 клиентов на Solution ID за 7 дней |

**Стоимость миграции кода — часы, а не недели.** 360dialog проксирует Cloud API один в один:
меняем базовый URL и `Authorization: Bearer` на `D360-API-KEY`, разбор вебхука
(`parseWaCloudEchoes`, медиа в два шага, шаблоны) остаётся как есть.

## Запасной вариант: Dualhook (план Platform)

$115/мес за 25 подключений (~$4.6 за WABA), дальше $4.5 за подключение. Coexistence,
мультиарендный API и со-брендированный онбординг, Webhook Override — вебхуки Meta летят прямо
на наш сервер, без посредника на пути сообщения.

**Почему не первый выбор:** Meta выставляет счёт каждому клиенту напрямую — то есть салон
обязан привязать карту (см. дедлайн 30.09.2026 ниже). Это ровно то требование, которое мы
хотели снять. Плюс мелкий вендор на критическом пути.

Брать, если 360dialog по цене за канал не уложится в наш потолок.

## Отклонено

- **Twilio.** Для Tech Provider Program требует **своё одобренное Meta приложение** — тот же
  блокер, из-за которого мы здесь. Плюс проприетарный API: транспорт пришлось бы переписывать.
- **Gupshup.** Путь для не-TPP партнёров есть, но coexistence не поддерживается — теряем
  «владелец ответил с телефона → ИИ замолчал», ключевую механику продукта.
- **Infobip / Sinch / Bird.** Энтерпрайз-минимумы, coexistence нет.
- **Оставаться на своём App Review.** Не отклонено, а отложено: заявку не отзываем. Своё
  приложение — минимальная себестоимость в долгую (только per-message, ноль за WABA). Но
  переезд арендаторов с 360dialog на свой Solution ID потребует повторного Embedded Signup для
  каждого салона — это цена опции, её надо закладывать.

## Что важнее выбора BSP

1. **Россия отпадает.** С февраля 2026 whatsapp.com исключён из НСДИ, веб-версия не открывается,
   мобильное приложение работает нестабильно; оснований для снятия ограничений РКН не видит.
   Не тратить бюджет WABA на российских арендаторов. Рынок — Кыргызстан и Казахстан,
   для РФ — Telegram/MAX.
2. **С 1 октября 2026 сервисные сообщения становятся платными.** Свободные ответы внутри
   24-часового окна — а это весь наш ассистент — будут тарифицироваться по ставке utility той же
   страны. Казахстан переводят на отдельный, более дорогой прайс. Плата за WABA ($5–12) — мелочь
   рядом с этим: тариф салона надо считать от сообщений, а не от фиксированной абонплаты.
3. **До 30 сентября 2026 нужен способ оплаты на счету.** У кого его нет — с 1 октября сервисные
   сообщения не доставляются. Модель Partner-Paid закрывает это нашим счётом; вариант
   «Meta биллит салон» — нет. Это делает требование «BSP финансирует биллинг» срочным.
4. **Embedded Signup v2 отключают 15 октября 2026** — интегрироваться сразу на v4.
5. **С 15 января 2026 Meta запретила универсальные ИИ-ассистенты в WhatsApp.** Наш ассистент
   привязан к бизнесу конкретного салона — это разрешённый сценарий; держать его в этих рамках.

## Порядок действий

1. Завести партнёрский аккаунт 360dialog, валюта USD или EUR — зафиксировать до первого счёта,
   меняется только через сейлза.
2. Задать сейлзу вопросы, от которых зависит решение:
   - цена за активный канал на плане Growth и платформенная плата за Partner Hub;
   - подтверждение Partner-Paid: салон вообще нигде не вводит карту;
   - поддержка бизнесов из Кыргызстана и Казахстана, наши способы оплаты счетов;
   - какие ставки за сервисные сообщения по KZ/KG с 01.10.2026;
   - PLBV для салонов без формальных документов.
3. Подключить Integrated Onboarding (Connect Button) в админку рядом с текущей вкладкой WhatsApp.
4. В `wa-cloud.server.ts` вынести базовый URL и схему авторизации в настройку канала: `meta`
   (Bearer, свой App) или `d360` (`D360-API-KEY`). Один адаптер, две реализации — чтобы переезд
   на своё приложение потом был переключателем, а не переписыванием.
5. Первый салон — через coexistence, с Green-API в гибриде, как в `WA-CLOUD-DEPLOY-CHECKLIST.md`.
6. Мост через Make снять сразу после первого успешного онбординга.

# AI Assistant Quality Test

Paid Gemini requests in this simulator share `qa/api-budget-local.json` with photo regression.
Each Flash request reserves $0.10 (Pro judge $0.25) before sending; testing stops at $2.99
reserved across repeated runs. Photo requests reserve $0.05 from the same ledger.
This is a conservative local guard, not a guarantee about other traffic on the Google project or
Google's delayed billing. Do not enable auto-reload for this test.

Система, которая разговаривает с ИИ-ассистентом Qabyl как десятки настоящих клиентов, проверяет
**фактическое состояние базы** после каждого разговора и выдаёт отчёт.

## Две части

| Часть            | Что проверяет                                                                                                  | Нужен ключ            | Запуск                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------- | --------------------- | -------------------------------------------------------------------- |
| **Живой прогон** | Качество разговора на настоящем Gemini: 71 сценарий, LLM-клиенты, независимый судья                            | да (`GEMINI_API_KEY`) | `bun run qa:assistant`                                               |
| **Harness**      | Детерминированные edge cases пайплайна: дубли вебхуков, пачки, гонка за слот, падение модели и базы, регрессии | нет                   | `bun test --isolate assistant-sim.harness` (входит в `bun run test`) |

## Как устроено

```
LLM-клиент (персона)  ──►  Meta-payload  ──►  processWaCloudPayload   ← настоящий код
                                                 ├─ дедуп, rate limit, сессии
                                                 ├─ замок разговора, слив очереди
                                                 └─ runWaAgentV4 → инструменты → create_appointment
                                                         │
                                  FakeSupabase (fake-db.ts) ◄┘  порты SQL-правил записи 1:1
                                                         │
             FakeTransport (что ушло клиенту) ◄──────────┘
                     │
      ┌──────────────┴───────────────┐
 assertions.ts (база = истина)   evaluator.ts (независимый судья)
      └──────────────┬───────────────┘
                 report.ts → reports/<время>/report.md + results.json
```

- **Подменены только две вещи**: клиент Supabase (→ `FakeSupabase`, через `preload.ts` по пути файла)
  и транспорт WhatsApp (→ `FakeTransport`). Вебхук, ассистент, инструменты, гарды — продакшн-код.
- **`fake-db.ts`** — порты `get_available_slots`, `create_appointment` (+ `assert_master_available`),
  `reschedule_appointment_v2`, предоплатного удержания, замка разговора, уникальных индексов и
  exclusion-ограничения. Источник истины — функции прода; при изменении SQL обновить порт.
- **Проверки по базе (`assertions.ts`)**: нужная запись (услуга/мастер/филиал/дата/время/статус),
  отсутствие лишних и двойных записей, мастер и услуга из того же салона, филиал = филиал мастера,
  длительность, «ассистент сказал “записал”, а записи нет / время не то», цены не из прайса,
  выдуманные мастера, потерянные сообщения, технический текст клиенту.
- **Судья (`evaluator.ts`)** получает истинные данные салона, переписку с вызванными инструментами,
  фактическое состояние базы и результаты проверок. Оценки 1–5 по 10 критериям.
- **Сценарий не проходит**, если провалена проверка уровня critical/high, или судья поставил
  `overall_pass=false`, средний балл < 3.5, или нашёл critical-проблему.

## Команды

```bash
bun run qa:assistant                      # вся библиотека
bun run qa:assistant --filter=B0          # по префиксу id, категории или тегу
bun run qa:assistant --filter=regression
bun run qa:assistant --concurrency=4 --repeat=3   # повторы ловят нестабильность модели
bun run qa:assistant --no-judge           # только проверки по базе
bun run qa:assistant --list
```

Переменные: `GEMINI_API_KEY` (обязательно). Для независимого судьи другой модели:
`SIM_JUDGE_PROVIDER=openai SIM_JUDGE_BASE_URL=… SIM_JUDGE_API_KEY=… SIM_JUDGE_MODEL=…`.
Клиент: `SIM_CUSTOMER_MODEL` (по умолчанию `gemini-flash-latest`), судья: `SIM_JUDGE_MODEL`
(по умолчанию `gemini-pro-latest`).

**Модели задавать алиасами, а не версиями.** Пин `gemini-2.5-pro` протух молча: Google закрыл его
для новых аккаунтов, судья начал падать с 404, и качество разговоров перестало проверяться вообще —
прогон при этом «работал», потому что проверки по базе от судьи не зависят.

**Бесплатный ключ полный прогон не потянет.** Лимит бесплатного тира — не скорость, а СУТКИ:
около 20 запросов на модель в день (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`). Одному
сценарию нужно ~15 вызовов, то есть бесплатного ключа хватает примерно на один сценарий в сутки.
Перед стартом прогон проверяет квоту одним запросом и честно отказывается, вместо того чтобы
крутиться полчаса и выдать пустой отчёт.

**Прогон тратит деньги.** 71 сценарий — это сотни вызовов модели плюс судья на pro. Полный прогон
способен выжрать весь Prepay-баланс Gemini, а он общий с продом: кончился баланс — замолчал
ассистент у салонов. Перед полным прогоном проверь остаток и включи auto-reload.

Прогон в реальную базу не ходит и сообщений не отправляет. Код выхода 1, если есть провалы.

## Жалоба салона → регрессионный тест

1. В `scenarios.ts` добавить сценарий: реальные первые сообщения клиента в `opener`, состояние
   салона в `setup`, правильный исход в `expect`, `category: "regression"`, `regression.bug` —
   одна строка про причину.
2. `bun run qa:assistant --filter=<id>` — убедиться, что падает по той самой причине.
3. Чинить **продукт**, не сценарий. Ослаблять `expect`, чтобы тест прошёл, нельзя.
4. Если баг детерминированный (не зависит от формулировок модели) — добавить кейс ещё и в
   `assistant-sim.harness.test.ts`, чтобы он проверялся в каждом `bun run test` без ключей.

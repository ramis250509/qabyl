# Чеклист перед выкладкой

Push в `main` = продакшн: Cloudflare деплоит автоматически, промежуточной проверки нет.
Самая частая поломка в этом проекте — не битый код, а **рассинхрон**: код уехал, а
миграция или edge-функция остались дома. Этот чеклист ловит именно это.

## 0. Заморозка

Сначала проверь память проекта на предмет действующей заморозки (например, на время
внешнего ревью Meta). Если заморозка есть — дальше не идёшь, докладываешь и
останавливаешься. Ничего не «применяем по-быстрому», пока идёт проверка.

## 1. Миграции: запусти сверщик

```
Supabase MCP → list_migrations (project bfxexnpyfslfuelfkhzr)
```

Сохрани полученный JSON в файл и прогони:

```bash
node scripts/check-migrations.mjs < db-migrations.json
```

Сверщик сравнивает по **имени** миграции, а не по номеру версии, и поэтому не
поднимает ложную тревогу. Он разделяет три разные ситуации:

- `[i] применены под другим номером` — **норма, чинить нечего.** Так выглядит любая
  миграция, применённая через MCP или дашборд: они присваивают свой номер по времени
  применения, имя при этом сохраняется.
- `[!] есть в базе, но нет файла` — миграцию накатили мимо репозитория. Схему нельзя
  развернуть с нуля. Вытащи SQL из `supabase_migrations.schema_migrations` в файл.
- `[X] не применены` — вот это настоящая работа. Но прежде чем применять, **проверь по
  объектам**: открой файл, выпиши, что он создаёт (колонку, значение enum, функцию,
  политику), и убедись запросом к `information_schema` / `pg_enum` / `pg_proc`, что
  этого в базе действительно нет. Миграцию могли накатить через SQL Editor мимо учёта.

Проект: `bfxexnpyfslfuelfkhzr` (Франкфурт, eu-central-1). Токийский
`khykprcdojksqvuqyajd` — пустой, трогать нельзя.

## 2. Edge-функции

`supabase/functions/`: `send-whatsapp`, `send-reminders`, `send-push`, `cleanup-wa-media`.
Они деплоятся **отдельно** от сайта — Cloudflare их не касается. Изменения в них,
уехавшие в git без редеплоя, не работают в проде.

```bash
git log --since="<дата прошлой выкладки>" --name-only -- supabase/functions/
```

Всё, что всплыло, попадает в чеклист с явной пометкой «нужен редеплой».

## 3. Тесты и линт

```bash
bun test
```

Ожидание — 758 прохождений, 0 падений, около 20-25 секунд.

`bun lint` **сейчас падает и на чистом репозитории** — порядка 42 тысяч замечаний
prettier по всему проекту, накопленных задолго до любой конкретной правки. Гонять его
целиком бессмысленно. Проверяй линт только по изменённым файлам:

```bash
node_modules/.bin/eslint <изменённые файлы>
```

Привести весь проект в порядок (`bun format`) — отдельная большая задача, не часть
выкладки: она перепишет форматирование сотни файлов и утопит любой полезный дифф.

## 4. Секреты

Если в правках появилась новая переменная окружения — она должна быть заведена в двух
местах: Cloudflare (для сайта) и Supabase Function Secrets (для edge-функций).
Проверь, что не забыто ни одно.

## Что выдать в конце

Короткий список пунктов, каждый — «сделано» / «нужно сделать: <точная команда>».
Ничего не применяй и не деплой сам без отдельной просьбы: задача чеклиста — показать
